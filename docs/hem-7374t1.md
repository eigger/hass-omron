# HEM-7374T1

Select **HEM-7374T1**, **HEM-7374T1-A2SHBK**, or **HEM-7374T1-A2SHDS**
during setup. These names share the existing HEM-7380T1 profile. The bare
`HEM-7374T1` name is also the GATT Model Number String reported by the tested
device, so it must resolve without a regional suffix.

## Profile evidence

The device configurations bundled in the official **OMRON Plus 5.2.8** Android
package identify both regional variants as `WLD3.0`. Their `OtherInfo.json`,
`SettingReadIndex.json`, `SettingWriteIndex.json`, and `VitalDataIndexes.json`
files are identical; `DeviceConfig.sys` differs only in the model ID.
The package is available through the [manufacturer's download page](https://www.omronhealthcare.com.cn/service/soft/download/1).

The relevant parameters match the existing profile:

| Parameter | Value |
| --- | --- |
| Service | `FE4A` |
| Host security / application unlock | OS bonding / token-key handshake |
| Record bank starts, users 1 and 2 | `0x01C4`, `0x0804` |
| Capacity | 100 records per user |
| Record size / stride | 16 bytes / 16 bytes |
| Record parser | `CLASSIC_VITAL_14` |
| Settings read / mirror write address | `0x0010` / `0x0054` |
| Index region | 24 bytes |
| Latest-position correction | `-1` |
| Clock block offset / size | `0x2C` / 16 bytes |
| Registration slot offset / size | `0x18` / 10 bytes |

Reusing the profile also retains its pairing-registration write and notify
subscription behavior. A read-only pairing-window session was insufficient
to retain the bond on the tested device. After the registration mirror and
clock block were committed, subsequent connections outside pairing mode
succeeded. Registration updates sync bookkeeping and the device clock; it
does not write the measurement banks.

## Hardware validation scope

On 2026-10-17, a device reporting firmware `SI.W03.00.03` and software
`0000000000300100` was tested with a standalone Bleak 3.0.2 program on macOS.
The probe used the existing token handshake and memory protocol, and the
project's unmodified `parse_classic_vital_14` record parser.

- GATT services, token echo, and memory-frame checksums were verified.
- Four historical readings across both users matched independently supplied
  user slots, dates, minutes, and systolic/diastolic values.
- After registration, a separate listener process reconnected outside pairing
  mode and read the existing records.
- A subsequent normal user-1 measurement was automatically detected and read
  without pressing the transfer button or using the phone app. Systolic,
  diastolic, and pulse values matched the monitor display. The observed time
  from advertisement reception to completed readout was approximately 2 seconds
  for that one measurement.

This is **protocol-level hardware validation**, not an end-to-end Home Assistant
or ESPHome-proxy hardware test. Automatic acquisition for user 2, power-cycle
recovery, long-term operation, and AFib/status flags have not been validated.
No personal measurements, device addresses, pairing keys, or raw captures are
included here.
